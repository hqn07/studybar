The leads

Ship these first

1

Slide OCR

LeadApple · freeS
Use cases
  • Photograph a lecture slide → text into the open note, while recording
  • Grab a slide already on screen (Zoom / PDF) as a region
  • Textbook page → flashcard; whiteboard photo → note
Recommended
Apple Vision VNRecognizeTextRequest(.accurate) + ScreenCaptureKit SCScreenshotManager for on-screen region grab; drag/paste image as the low-tech path.
Rejected
Tesseract — less accurate on Apple, extra dep, no benefit. Vision wins on quality + it's already integrated.
Integration
reuse Reading-module Vision OCR · add "Insert from slide" in Notes + recording bar
Caveat
Vision reads printed text well; math on slides degrades to plain text.
2

In-app local AI

Lead · strategicMITL
Use cases
  • Summarize · organize transcript · plan-my-day · flashcards-from-note · syllabus extract
  • All with zero setup — no Ollama install, works offline on a fresh machine
Recommended
mlx-swift + mlx-swift-examples (MLXLLM) running a 4-bit Qwen2.5-3B-Instruct (matches the qwen family you already prompt) or Llama-3.2-3B. Tokenizer via swift-transformers.
Rejected
llama.cpp — works, but mlx is native Swift + Metal-tuned + Apple-maintained. Apple FoundationModels (your existing OnDeviceProvider) — gated to macOS 26 + Apple Intelligence; MLX runs on any Apple Silicon → broader zero-setup path.
Integration
new MLXProvider: AIProvider + AIMode.onDeviceMLX · reuse JSON-action protocol + Whisper-style model download
Harden what shipped

Recorder upgrade

3

Better Whisper chunking (VAD)

UtilityMITBSDS→M
Use cases
  • Cut chunks at real pauses; kill the intermittent blank / len-0 chunks
  • Less lag between speech and transcript on long lectures
Recommended
WebRTC VAD / libfvad (BSD, tiny C, no ML runtime) for a pragmatic robust VAD — or Silero VAD converted to Core ML (MIT) for best accuracy, still native.
Rejected
Bundling onnxruntime just for VAD — too heavy for the payoff. Convert Silero to Core ML instead if you want the ML model.
Integration
replace the RMS-threshold logic in VoiceService.cutChunk / pause detection
Quality & retrieval

Cheap robustness, then search

4

Semantic note search

UtilityApacheM
Use cases
  • "Find related notes" by meaning, not keyword · suggest [[links]] · flag near-duplicates
Recommended
swift-transformers running bge-small-en-v1.5 / all-MiniLM-L6-v2 as Core ML embeddings + brute-force cosine in Swift (you have hundreds of notes — no vector DB needed yet). Graduate to USearch / sqlite-vec at thousands.
Rejected
NLEmbedding — already rejected (weaker; lost to keyword on math PDFs). This is over clean note text with a real sentence-transformer.
Integration
extend UnifiedSearchView (semantic mode) · embed notes on save
5

Robust Markdown

UtilityApacheS→M
Use cases
  • Kill the previewText regex leaks for good · reliable outline extraction · clean export
Recommended
swift-markdown (Apple, cmark-gfm) for a real AST — walk it for plaintext / outline. Keep KaTeX / SwiftMath for rendering.
Rejected
Ripping out the renderer — swift-markdown doesn't render to SwiftUI. Use it for parsing/stripping only; keep the existing preview.
Integration
replace Note.previewText regex chain + editor outline with AST walks
6

Auto-tagging / NLP

UtilityApple · freeS
Use cases
  • Suggest tags from note content · detect note language (feed Whisper / spellcheck)
  • Pull key terms / people / dates for search + link suggestions
Recommended
Apple NaturalLanguage — NLTagger (lexicalClass, .nameType entities), NLLanguageRecognizer, NLEmbedding.wordEmbedding for word-level similar-terms. Nothing to bundle.
Rejected
A bundled NER model — overkill; NaturalLanguage covers tags/entities/language on-device for free.
Integration
feed the existing tag-autocomplete a "suggested tags" source · language → VoiceService

Scope it small

7

Read-aloud (TTS)

SituationalApple · freePiper MITS→M
Use cases
  • Proofread an essay / notes by ear · accessibility · eye-rest review
  • Flashcard front → back audio · export note → .m4a for a phone (bridge)
Recommended
AVSpeechSynthesizer first (free; prefer .premium/.enhanced voices, nudge the user to download one). Math layer (required for STEM): run SRE (Speech Rule Engine) inside the already-bundled KaTeX WKWebView — KaTeX→MathML→SRE→spoken string. Upgrade voice later with Piper/Kokoro.
Rejected
Raw TTS on note text — reads LaTeX as gibberish; math needs the SRE layer. MathCAT (Rust) is the alternative math engine but heavier than SRE-in-webview.
Integration
note → previewText strip → SRE for $…$ → AVSpeech · export via AVSpeechSynthesizer.write(to:)
Reality
Mac-only kills the commute case; free voices are decent-not-great. Core value = proofreading + accessibility only.
Foundations · when the goal is sync/scale

Big bets

8

Real multi-device sync (CRDT)

FoundationMITL
Use cases
  • Mac ↔ future iPhone conflict-free sync · offline edits merge cleanly
  • The delete-resurrection class solved structurally, not by hand
Recommended
automerge-swift (official Rust-core bindings). Transport: CloudKit (Automerge binary in a CKRecord) or the existing iCloud Drive file. AppData becomes an Automerge doc.
Rejected
Yjs — JS, not Swift-native. Automerge-swift is the fit and replaces the hand-rolled mergeLists.
Integration
migrate/dual-write the JSON store to an Automerge doc · retire AppData.merged
9

SQLite store + FTS5

Foundation · deferMITL
Use cases
  • Fast full-text search on a heavy notebook · scale past whole-JSON loads · migrations
Recommended
GRDB.swift — FTS5 built in, and it can load sqlite-vec to unify with semantic search (#4).
When not
You're at ~200 assignments / 8 notes — JSON is fine. Adopt only when it outgrows that; then it also powers #4's vectors.
Integration
replace the JSON AppState store; migrate on first launch
Sequencing

Build order

By value-per-effort and shared infrastructure — cheap wins and recorder-hardening first, the strategic AI bet next, foundations when sync/scale is the goal.

1
Slide OCR (#1 · S · reuses Vision)

Ship the capture-loop win — desk-native, small, no new deps.

2
VAD chunking (#3 · S→M)

Harden the recorder you just shipped — fewer blank chunks, less lag.

3
Auto-tags + swift-markdown (#6, #5 · S / S→M)

Cheap quality & robustness; kills the previewText leaks.

4
MLX in-app AI (#2 · L · strategic)

Zero-setup AI; brings swift-transformers into first-class use.

5
Semantic search (#4 · M · rides #4 infra)

Reuses the embedding stack from the AI work.

6
Automerge → GRDB (#8, #9 · L)

Foundations — when multi-device sync / scale becomes the goal.

7
Read-aloud (#7 · opportunistic)

Scoped to proofread + accessibility (AVSpeech + SRE math).
